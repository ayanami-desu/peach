# ADR-0163：删掉自动 Mix

- 状态：已采纳
- 日期：2026-11-14
- 关系：修订 ADR-0008 中「自动 Mix 是一次临时推荐，用户保存后成为播放列表」的结论；ADR-0031 的组件文件名随之下调；其余各条不变

## 背景

首页网格每累计八张作品就在第八位插一张自动 Mix 卡：种子取附近有图有署名的作品，点开 `/mix/{seed}/{id}` 进详情后，右侧队列变成一份临时推荐；详情页另有「保存 Mix」，把它复制成 `source_kind='mix'` 的播放列表。它带来三套只服务这一个入口的东西：首页的插入位置与种子挑选、`/api/mix` 的推荐取数、播放列表的 Mix 来源字段与 `mixRelated` 取数；而队列展示本身与分卷、版次、播放列表共用。

用户从未使用过这个功能，要求删到像从未存在，不保留旧地址、旧参数、旧列或旧组件名。

## 决策

**一、首页只画作品。** `catalog-grid` 的排法改为 `arrangeCards`，只做折叠与跨页去重；`mix` 版式参数、`MIX_SLOT`、`arrangeTiles`、`mixSeed` 与 `HomeMix` 组件删除。首页、未看、稍后看、标记与回收站共用同一张网格，都不再出现 Mix 卡。

**二、推荐取数与入口全部删除。** `/api/mix`、`mixRelated`、`/mix/{seed}/{id}` 页面路由、详情里的 `mix` 队列分支与「保存 Mix」入口一并移除；`/assets/{id}?mix=...` 没有读取方，按普通详情打开。旧 `/mix` 地址直接 404，不做重定向。

**三、播放列表删掉来源字段。** 迁移 `0059_drop_playlist_source.sql` 重建 `playlist` 与 `playlist_item`，删除 `source_kind`、`source_seed_asset_id`；`w_playlist` 的读写不再出现来源字段，批量删除与消失行接回也不再清理种子引用。播放列表本身、条目顺序与续播位置保留。

**四、共用组件改成中性名。** 播放列表叠放卡 `MixCard` 改为 `PlaylistCard`，详情队列壳 `MixQueue` 改为 `QueuePanel`，`MixQueueRow` 改为 `QueuePanelRow`；`MIX_FLIP_*` 改为 `STACK_FLIP_*`，`mixFace` 改为 `mediaFace`，`mixLabel` 改为 `queueLabel`；`data-mix-*` 改为 `data-playlist-*` 或 `data-detail-queue-*`。CSS、e2e 与单元测试同步更新。

**五、不保留兼容层。** 不保留旧组件名、旧属性名、旧列、`/mix` 重定向或 `?mix` 特判；ADR 是这次删除的唯一记录。

## 被否决的方案

- **保留 `/mix` 307 与 `?mix` 解析。** 旧链接只会进入一份无法解释的推荐，用户从未使用过，兼容成本没有收益。
- **保留 `source_kind`、`source_seed_asset_id` 列。** 列一旦留下，读写代码与清理逻辑就会继续围绕一个不存在的功能分叉；用户没有存量数据，直接删列。
- **保留 `MixCard`、`MixQueue`、`data-mix-*` 作为内部名。** 功能已经不在，名字仍会让下一次改动误以为还有 Mix 入口；全部改成它实际承担的播放列表与队列语义。
- **连同播放列表一起删。** 播放列表是独立功能，自动 Mix 只是它曾经的一个创建来源。

## 后果

- 首页卡片密度回到纯作品；不再有「第八位」的空档或推荐卡。
- 旧的 `/mix/{seed}/{id}` 地址返回 404；带 `?mix=` 的详情链接按普通详情打开，参数没有读取方。
- 播放列表的列表、顺序与续播位置不受迁移影响；来源列删除后，新建与读取都不再出现 `source_kind`。
- 代码与样式里不再有 Mix 组件、属性或路由名；ADR-0008 与 ADR-0031 保留当时的设计记录，ADR-0031 的文件路径改为新名字。
