# ADR-0148：JavDB 匿名接口按主机冷却，签名材料有备用

- 状态：已采纳
- 日期：2026-11-05
- 关系：修订 [ADR-0144](0144-javdb-scraping-uses-the-anonymous-api.md) 第五条「撞上 403/429 时接口整源冷却 15 分钟」；间隔、预算与快照复用不变

## 背景

匿名接口只依赖两个主机：签名常量从网页前端 `catembylegacy.fastcdn.dpdns.org` 读取，请求只发往 `jdforrepam.com`。
任何一个被墙、DNS 解析失败或宕机，JavDB 这一档就整源冷却，作品资料抓取与馆藏探索一起停。

另一个开源项目 javmoe（GPL-3.0）移植了 MDCx 的 JavDB App 适配：用写死的 App 签名材料，并按顺序尝试
`apidd.czssdgz.com`、`apidd.spthgb.com`、`jdforrepam.com` 三个主机。2026-11-05 经用户同意，在本机同一出口
实测：三个主机分别用网页签名和 App 签名，各做一次 `SSIS-589` 搜索和一次详情请求，共 12 个请求，全部 HTTP 200
且 `success: 1`。六组详情的作品 id、番号、类别数、预览图数、预告与封面主机都相同；镜像每次请求慢 0.25～0.45 秒。
搜索结果第一条在各组都一样，第二、三位的次序不固定。

镜像与 `jdforrepam.com` 是否共享按 IP 计的配额，只有撞上 403/429 才看得出来，实测没有取得。

## 决策

**一、接口主机按序使用、各自冷却。** `API_HOSTS` 依次为 `jdforrepam.com`、`apidd.czssdgz.com`、`apidd.spthgb.com`。
一个主机连接失败、回非 200 或回的不是 JSON 时，只冷却这一个主机（403/429 冷却 15 分钟，其余 60 秒），同一请求
交给下一家。三家都在冷却时才整源停，`paused_until` 取最早恢复的那一家。按用户 2026-11-05 的决定，镜像先当作
与主主机配额不共享处理。业务层的失败（`success` 不为 1、数据形状不对）仍整源冷却 60 秒：三家是同一份数据，换主机
答复不会变。

**二、签名材料有备用。** 网页前端连不上、或入口脚本里认不出签名计算式时，改用 App 那一套签名材料，并按实测通过的
形态一起发送设备参数、`Dart/3.5` 用户代理与 `accept-language: zh`。一小时后再回头读网页前端；网页前端那一路的
失败只冷却它自己，不让整源停。App 签名材料随 App 版本更新可能失效，所以只当第二来源，不替换运行时读取。

**三、每问预算放宽到 6 次请求。** 刮削一问原本是签名常量两次、搜索、详情共 4 次；冷启动时再换一次主机就超出。
多留两次给换主机。

## 影响

- 单个主机或网页前端出问题时，接口照常可用；镜像接替时每部片约多 0.5～1 秒。
- 如果镜像与主主机实际共享配额，撞上 403/429 后会在三家上各撞一次再整源停，比原来多两次被拒的请求，
  之后照常冷却。出现这种情况时把第一条改回「403/429 整源冷却」。
- 视频预览的 `preview_video_url` 校验仍只认 `jdforrepam.com`；镜像给出的预告地址如果落在镜像主机上，这一部的预告
  显示为不可用。未取得镜像返回的预告地址形态。
- 只借鉴主机名与签名格式这类协议事实，不复制 javmoe 的代码。
