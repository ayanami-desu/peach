# ADR-0160：永久删除把网盘文件移进回收站，移不成的行留在账本

- 状态：已采纳
- 日期：2026-11-13
- 关系：补上 [ADR-0157](0157-remote-drive-api-storage-and-playback.md) 留下的删除缺口；修正 [ADR-0080](0080-resource-sync-owns-empty-folders-and-purges-vanished-rows.md) 决策二末句「不碰媒体文件」。

## 背景

ADR-0157 之后媒体只在网盘上，账本行带 `remote_id` 与 `drive_root`。永久删除一直只删账本行，界面文案却写「已永久删除 N 个影片文件」：用户从数据管理批量删除后，网盘上的原文件还在，只能去网盘里逐个找。文件仍在盘上时，下一次全量核对会按 `(location, remote_id)` 重新插入一行，拿到新 id，原来的观看记录、标签与元数据接不回去。

ADR-0080 决策二的「不碰媒体文件」是资源同步的边界：自动判定不能让 Peach 替用户删片。用户在确认框里点下的永久删除是另一回事，它本来就宣告「删除后无法恢复」。

## 决策

**一、驱动协议加删除，文件进网盘回收站。** `drive_provider.DriveProvider` 新增 `delete(remote_id)`。Google 用 `PATCH /files/{id}` 带 `{"trashed": true}`，OneDrive 用 `DELETE /me/drive/items/{id}`：两边都是把项目移进该网盘自己的回收站，不在 Peach 里直接销毁。扫描只看未入回收站的项目，所以账本行删掉后不会再被同步回来；要彻底清掉时，用户去网盘回收站自己清空。

**二、先移文件，再删行；移不成的行留下。** 远端阶段在写事务之外逐条执行，每条前过 `task_control.checkpoint()`。文件已经不在返回 `DriveNotFound`，算删成功；其余 `DriveError` 进 `blocked`，理由写成「网盘文件没能移进回收站：…」，该行整条留在库里，前端按现有 `blocked` 列表展示。远端阶段完成后才开写事务删账本行。

**三、没有远端 id 的行只删账本行。** 旧来源（115、PikPak、光鸭、已挂载网盘）与本机文件的 `remote_id` 为空，没有可删的对象；已标 `vanished` 的行同理，直接跳过远端阶段。数据管理页的孤儿记录也走这一支。

**四、清单在动文件前后各核一次。** 女优删除先核一次选中清单，再移远端文件；写事务里再核一次才删行。这期间清单变了就整批放弃：已经删掉的文件对应的行留着，下次扫描会把它们标成已消失，等用户确认。

## 影响

- 现在点永久删除会把网盘文件移进对应网盘的回收站；账本记录不可恢复，文件还能在网盘回收站里找回。确认框文案已改成「原文件移到网盘回收站」。
- 网盘凭据失效、限流或服务不可用时，文件移不进回收站，对应的行整条留在 `blocked`，需要在凭据修好后重试。没有接入对应驱动时同样拒绝，不再静默只删行。
- 字幕文件是独立的 `asset` 行，删视频只解除 `asset_subtitle` 配对。本机缓存（快照、海报、缩略图）仍按 `asset_id` 命名，行删后成孤儿，存储页只支持整类清理。
