# Vercel Forms：什么时候配提交按钮，什么时候回车就够

- 取证日期：2026-09-03
- URL：<https://vercel.com/design/guidelines>（Forms 一节）
- 取证方式：浏览器加载页面后读正文
- **不在 `docs/reference-sources.json` 里登记**：这一页是 React 渲染的，抓下来的 HTML
  没有可哈希的上游快照。仓库里已登记的 `vercel-web-interface-guidelines` 取自
  GitHub 上那份 `command.md`，是同一套规范的精简版，Forms 一节缺下面这几条。

## 规范里的四条（本次取到的原文要点）

| 条目 | 规范怎么说 |
| --- | --- |
| 回车提交 | 文本输入获得焦点时，**若它是表单里唯一的控件，回车即提交**；控件多时把这条落在最后一个控件上 |
| textarea | `<textarea>` 里 ⌘/⌃+Enter 提交，回车插入换行 |
| 提交按钮的状态 | 提交发起前保持可用，发起后禁用并显示 Spinner，带幂等键 |
| 不要预禁用 | 不许因为表单没填完就禁用提交；允许提交以便暴露校验反馈 |

## 由此得到的判据

规范没有「搜索不配按钮」这一条，它给的是更一般的分界：

- **只读、没有副作用的查询**（搜索、筛选）——控件本来就只有一个输入框，回车即执行，
  按钮是多余的第二个入口。配套模式是 Search Input：搜索图标前缀，查询中原位换 Spinner。
- **有副作用的提交**（写入、删除、付款）——按钮必须在，它同时是「这一步会改东西」的
  声明和一个可以进入忙态、可以显示 Spinner 的落点；回车仍然要能提交，两者并存。
