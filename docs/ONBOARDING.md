# 第一次打开

装好之后到能播上一段视频，中间只有四步：完成首次设置、接上网盘、选扫描根、等第一轮同步。这篇按这个顺序走一遍。运维细节见[运行与配置](OPERATIONS.md)，容器相关的准备见 [Docker 部署](DOCKER.md)。

## 首次设置

浏览器打开服务地址。首次设置页问的东西随运行形态不同：

| 运行形态 | 页面上会问 |
| --- | --- |
| Docker | 网盘公网地址、访问密码 |
| 源码运行 | 数据目录、监听地址、端口、网盘公网地址、访问密码 |

容器里的数据目录固定 `/data`、监听固定 `0.0.0.0:8900`，所以这三题不问，由建容器时定。

- **网盘公网地址**：浏览这个服务时用的对外地址，必须 https，例如 `https://peach.example.com`。网盘授权的回调地址就是它加上 `/oauth/gdrive/callback` 或 `/oauth/onedrive/callback`。现在还不知道域名可以先留空，之后在设置页「网盘」里补；留空时授权入口会拒绝发起。
- **访问密码**：8–256 个字符，两次输入要一致。留空表示这台服务免登录。密码之后可以在设置 → Peach 配置 → 网络与访问里改，改完所有设备都要重新登录。

提交后服务会建好数据目录下的八个子目录、把账本迁到最新结构、写入访问策略与 `config.toml`，然后跳到 `/?onboarding=1`。

源码运行时首次设置只接受从本机回环地址发起的提交；想让另一台机器打开设置页，先在服务器上跑 `peach init`。已经配置完成的实例，设置接口一律返回 404。

## 接上网盘

两个来源各自要一套 OAuth 客户端凭据，申请步骤（Google Cloud 项目、Entra 应用、回调地址、需要的范围）见[运行与配置](OPERATIONS.md#申请网盘-oauth-客户端)。凭据写进 `config.toml` 的 `[drive.accounts.<网盘>]`，重启服务。`GET /api/drive` 里该来源的 `configured` 从 `false` 变成 `true`，就说明凭据读到了。

1. `POST /api/drive/<网盘>/authorize` 拿到授权地址，浏览器打开，在网盘一侧同意
2. 回跳落在 `/oauth/<网盘>/callback`，服务把令牌写进 `secrets/drive-accounts.json`，`GET /api/drive` 里的 `connected` 变成 `true`，并带上账号邮箱或显示名
3. `GET /api/drive/<网盘>/folders?parent_id=` 逐层看远端目录，`POST /api/drive/<网盘>/roots` 提交要扫的目录 id

授权的一次性回执 15 分钟内有效。中途关掉标签页、换了网盘、或者服务重启过，重新发起一次授权就行。目录选择写回 `config.toml` 的 `[drive.roots]`，之后手改这一节和调接口是同一件事。

## 等第一轮同步

服务启动后的一分钟内就会开始第一轮核对：先列目录、把文件登记进账本，再按需取缩略图。之前同步过的来源只追增量，每 15 分钟一轮，超过一天没做全量核对就整棵重扫。

想立刻看到结果，调 `POST /api/drive/<网盘>/refresh`，它把这个来源排到下一轮先做（最多等一个循环，60 秒）。同步失败不会卡住别的来源，错误记在该来源的 `last_error` 上，下一轮重试。

同步完成后，馆藏里就有内容了。播放直接走网盘：OneDrive 给浏览器一个预授权地址，Google Drive 由 Peach 转发 `Range` 请求，本机不留视频副本。浏览器自己能不能解这个容器与编码决定能不能播，服务端不做转码。
